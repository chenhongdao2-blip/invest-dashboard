# ── PR4 storage split (audit R3 §6/§8.2) ─────────────────────────────────
# BOTH pinned EXACTLY, and the pins are load-bearing:
#   pyarrow — the writer version is embedded in every parquet footer's `created_by`,
#     and a minor bump can change dictionary encoding. An unpinned bump silently
#     re-churns every committed partition, which is the exact churn this split exists
#     to stop. tests/test_parquet_store.py asserts byte-determinism; a bump must be
#     accompanied by a deliberate one-off rewrite of the store.
#   duckdb  — a minor bump can change ORDER BY / aggregate edge behaviour, which is
#     what the read-side cutover (a later PR) will be diffed against.
# pandas is deliberately NOT pinned here. It used to reach the footer too — pyarrow's
#   `store_schema=True` writes a `pandas` key carrying `pandas_version` verbatim, so a
#   2.3 → 2.4 bump would have re-churned every rewritten partition while untouched ones
#   kept the old string. `jobs/parquet_store.py` now writes `store_schema=False`, and
#   `tests/test_parquet_store.py::test_the_footer_carries_no_pandas_metadata` keeps it
#   that way, so the version range below is free to move again.
pyarrow==24.0.0              # jobs/parquet_store.py writer — see determinism note above
duckdb==1.5.5                # jobs/parquet_store.read_table + jobs/parity_check.py
