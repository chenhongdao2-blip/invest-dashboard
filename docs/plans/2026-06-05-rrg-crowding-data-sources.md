> 本文只盘「护栏②=拥挤度叠加层」的数据可达性，最小测试已跑，结论落盘。

## 最小测试结论一句话

**护栏②不是单一指标，是两层**：per-sector 拥挤度叠加（图上标红）+ market-level 风险偏好闸（全局水印）。
A 股能做真·板块级拥挤；美股 AAII/COT/GEX 全是**大盘级**，不是板块级——这是本次测试最重要的发现。

## 结构性发现 → 重画护栏②为两层

```
护栏② 拥挤度
├─ Tier A · per-sector 叠加层（Leading 板块标红 + [BLOCKER:微观过热]）
│   A股 : iFind 成交占比 z-score + 换手率 z-score        🟢 ready
│   美/港: 板块内部 breadth/extension（%>50DMA、RSI拉伸、
│          相对成交量、头部个股成交集中）——从已有成分股 EOD 自算
│          ⚠️ NOT AAII/COT/GEX（那些是大盘级）              🟡 待建
│
└─ Tier B · market 风险偏好闸（全站水印 / 全局踩刹车，喂 L0+L1.5）
    美股: AAII + COT(Leveraged Funds) + GEX(flip 符号)      🟢 ready(免费档)
    A股 : 两市总成交额 z-score + 融资余额 + 涨停家数         🟢 iFind ready
```

**关键纠偏**：周期 agent 说「美股换成 CTA/Gamma/AAII」——实测后精确化为：那三者是 **Tier B 大盘闸**，不是 Tier A 板块叠加。美/港的板块级拥挤必须走「板块内部 breadth」，而 breadth 用我们 `benchmarks_daily`/成分股 EOD **本来就能自算**，不依赖任何付费源。

## 实测验证（2026-06-05 端到端，申万一级行业）

**RRG 主数据缺口已摸清——结论：一个 iFind 源搞定 RRG 核心 + 拥挤度 Tier A，零付费依赖。**

iFind 数据管道事实（实测，写进 data job 必须遵守）：

| 事实 | 细节 |
|---|---|
| 申万行业指数代码后缀 | **`.SL`**（不是 `.SI`！`.SI` 返回空）。用中文名"申万XX指数"查最稳 |
| 单次调用可同时取 | **收盘点位 + 每日换手率 + N日成交额**（`index_data`，一次到位）|
| 响应行数上限 | **~80 行/次** → 250 日历史需**分 ~4 次窗拉**，逐窗拼接 |
| 多实体合并查询 | **会被压成单实体**（首查 4 实体只回沪深300）→ 必须**逐行业调用** |
| `sector_data` 长窗口 | 60 日返回空（6 日可）→ **弃用，改 `index_data`** 拿换手率 |

端到端最小测试（医药生物 vs 沪深300，60 日窗口）：
- RS 线 170.0 → 148.6（医药明显跑输）；换手率 z = **−1.18**（冷却，不拥挤）
- ✅ RRG 象限 + 拥挤度 z 全部从 **1 个 iFind 源**算出，零付费
- ⚠️ **诚实信号**：60 日窗太短，SMA21 后仅 ~40 有效点，象限被归一化噪声打成"Improving"，但 RS 线明摆着在跌（实质 Lagging）。**这反而验证了两件事**：① 生产必须 250 日历史；② RRG 短窗象限翻转=噪声，坐实周期 agent"RRG 是状态描述非方向预测"的护栏。

**Data job 形态**：31 申万一级 × ~4 窗/行业 ≈ **124 次调用**，批处理加 sleep，落新表 `sw_industry_daily`（收盘+换手率），与 `benchmarks_daily` 并列。
